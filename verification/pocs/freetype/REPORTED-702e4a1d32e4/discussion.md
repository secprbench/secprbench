## title
FreeType gvar glyph coordinate pool underallocation

## bug_discussion
Upstream GitLab MR !371 (https://gitlab.freedesktop.org/freetype/freetype/-/merge_requests/371) states that the allocation regression was introduced by 582de1a4b6f6269bdb358605f9b23406988cd5b5. The mainline fixing commit 702e4a1d32e4b911e85cc7df84b3ba395c28dab3 states 'Fix allocation' and adds sizeof(*peak_coords) to the peak coordinate pool size. The captured ASan preflight using one controlled variable-font input shows a heap-buffer-overflow write on the introducing revision and clean runs on its parent and the fixing revision. No separate public bug report, upstream PoC, or committed regression test was found. Security review, construction, and Docker verification remain pending.
